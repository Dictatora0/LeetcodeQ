# 为什么有负数时，普通滑动窗口会失效

这一页专门解释一个很常见的误区：

```text
看到“连续子数组”就想上滑动窗口
```

这在很多题里是对的，但有一个非常关键的前提：

```text
窗口状态必须随着左右指针移动保持某种单调性
```

而“区间和”相关题一旦允许负数，这个前提往往就没了。

## 先看滑动窗口为什么在非负数组里好用

以“求和为 k 的最长子数组”或“和不超过 k 的最长子数组”为例。

如果数组里所有数都 `>= 0`，那么：

- 右指针右移，窗口和只会不变或变大
- 左指针右移，窗口和只会不变或变小

这就意味着：

- 如果当前窗口和太大，可以放心移动左指针来减小它
- 如果当前窗口和太小，可以放心移动右指针来增大它

也就是说，窗口和关于指针移动是“可预测”的。

## 一旦有负数，单调性就没了

如果数组里允许负数：

- 右指针右移，窗口和可能变大，也可能变小
- 左指针右移，窗口和可能变小，也可能变大

于是原来滑动窗口依赖的“太大就缩、太小就扩”逻辑就不可靠了。

## 反例 1：右移右指针后，和可能变小

数组：

```text
[5, -10, 8]
```

窗口一开始是 `[5]`，和为 `5`。

如果右指针右移一格，窗口变成：

```text
[5, -10]
```

和反而变成 `-5`。

所以：

```text
右移右指针 != 一定让和变大
```

## 反例 2：右移左指针后，和可能变大

还是看：

```text
[5, -10, 8]
```

如果窗口是整段 `[5, -10, 8]`，和为 `3`。

现在左指针右移一格，窗口变成：

```text
[-10, 8]
```

和从 `3` 变成 `-2`。

再把左指针右移一格，窗口变成：

```text
[8]
```

和从 `-2` 变成 `8`。

所以：

```text
右移左指针 != 一定让和变小
```

## 为什么“和为 k”时普通滑窗尤其容易错

很多人会写这种思路：

1. 右指针扩张窗口
2. 如果当前和大于 `k`，就移动左指针缩小窗口
3. 如果当前和等于 `k`，更新答案

这在“所有数非负”时常常可行。

但有负数时会漏解。

### 具体反例

数组：

```text
[1, -1, 5, -2, 3]
```

目标：

```text
k = 3
```

正确答案是前 4 个数：

```text
1 + (-1) + 5 + (-2) = 3
```

长度为 `4`。

如果你用“和大于 k 就缩”的普通滑窗：

- 先拿到 `[1, -1, 5]`，当前和是 `5`
- 因为 `5 > 3`，你可能会移动左指针
- 但接下来如果再读到 `-2`，原本这个负数是能把总和拉回到 `3` 的

也就是说，你过早缩窗，把本来正确的最长解破坏掉了。

## 什么时候滑窗仍然能用

有负数并不意味着“所有滑窗都不能用”，而是：

```text
依赖区间和单调性的普通滑窗经常失效
```

下面这些情况仍然可以用滑窗：

- 固定长度窗口
  例如长度恰好为 `k` 的最大和
- 不依赖区间和单调性，而依赖字符频次、重复性、种类数等状态
  例如最长无重复子串
- 题目明确保证数组元素非负

## 和记忆法

可以记一句话：

```text
非负数组里，窗口和跟指针移动方向基本同向；
有负数时，这种同向关系断了，普通滑窗就不稳了。
```
