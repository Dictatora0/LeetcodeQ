
# 动态规划模式指南

## 一眼识别信号（3 秒判断）
- 题目问“最优值”（最大/最小）或“方案数”
- 当前决策依赖之前若干状态，不是单纯贪心局部决策
- 暴力递归可写，但会重复计算相同子问题
- 能清晰描述“状态 + 转移”

## 先做 DP 三连问
1. `dp[i]` / `dp[i][j]` 到底表示什么？
2. 当前状态如何由更小子问题转移而来？
3. 初始值和遍历顺序是什么？

## 常见题型分类
- 线性 DP：
  单序列推进，如爬楼梯、打家劫舍、最大子数组和
- 网格 DP：
  二维坐标状态，如最小路径和、不同路径
- 背包 DP：
  有“容量 + 选择物品”结构，区分 0-1 与完全背包
- 序列匹配 DP：
  双序列对齐，如 LCS、编辑距离
- 区间 DP：
  枚举区间长度再转移，如戳气球、回文相关

## 状态设计模板
- 一维状态：
  `dp[i]` 表示前 `i` 个元素范围内的最优值/方案数
- 二维状态：
  `dp[i][j]` 表示两个维度约束下的答案（位置、容量、区间）
- 布尔状态：
  `dp[i]` 表示“是否可达/是否可行”

## 转移方程常见形态
- 选 or 不选：
  `dp[i] = max(不选 i, 选 i)`
- 从多个前驱转移：
  `dp[i] = min/max(dp[prev] + cost)`
- 计数累加：
  `dp[i] += dp[prev]`

## 遍历顺序判断口诀
- 如果状态依赖“更小索引”：
  从小到大遍历
- 0-1 背包（每件只能用一次）：
  容量倒序
- 完全背包（可重复使用）：
  容量正序
- 区间 DP：
  先枚举区间长度，再枚举起点

## 从递归到迭代的落地步骤
1. 先写记忆化 DFS，验证状态定义正确
2. 把递归参数映射到数组维度
3. 按依赖关系确定迭代顺序
4. 做空间压缩（如 `dp[i]` 仅依赖前一行）

## 高频易错点
- `dp` 定义模糊，导致转移和初始化都错
- 初始化只写“默认 0”，但语义需要 `INF` 或 `-INF`
- 遍历顺序错误，导致“重复使用同一物品”
- 把“最值问题”和“计数问题”混用同一转移

## 面试口述模板（30 秒）
- “这题有重叠子问题和最优子结构，适合 DP。”
- “我定义 `dp[...]` 表示 `...`，转移来自 `...`。”
- “初始化是 `...`，遍历顺序按依赖关系是 `...`。”
- “时间复杂度 O(...)，空间复杂度 O(...)，可进一步压缩到 O(...)。”
