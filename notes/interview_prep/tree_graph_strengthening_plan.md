# 树与图专项强化手册

## 目标

两周内把“会做题”提升到“能稳定识别、能口述、能应对追问”。

目标拆解：
- 看到题面 20 秒内判断是树还是图、用 DFS/BFS/拓扑/并查集中的哪一个
- 能手写 4 个核心模板：树递归、图 DFS、图 BFS、拓扑排序
- 每道代表题能 60 秒讲清：状态定义、不变量、复杂度、边界

## 你的薄弱点画像（常见）

树和图卡住，通常不是“代码不会写”，而是这三类问题：
- 识别慢：不知道该用 DFS 还是 BFS
- 递归语义不稳：函数返回值定义混乱，导致后序合并出错
- 口述空洞：只会说“遍历一下”，说不出为什么正确

## 先建立识别框架（面试第一分钟）

看到题目先问 5 个问题：
1. 是否要求最少步数 / 最短路径？
2. 是否要按层输出 / 最近层结果？
3. 是否有先后依赖关系（A 必须在 B 前）？
4. 是否反复做“连通性查询 + 合并”？
5. 是否需要从子树返回信息再合并到父节点？

决策：
- 最少步数、层序：BFS
- 依赖关系：拓扑排序
- 动态连通：并查集
- 子树信息合并：树 DFS（后序）
- 枚举路径：DFS + 回溯

## 高频面试追问清单（树）

1. 你这个递归函数返回值语义是什么？
2. 为什么必须后序而不是前序？
3. 如果节点数到 1e5 会不会栈溢出？
4. 这题能改成迭代吗？
5. 如何从 O(n) 空间优化？

标准回答方向：
- 明确返回值语义
- 说明合并时机
- 给出迭代替代（栈/队列）
- 分析最坏栈深

## 高频面试追问清单（图）

1. 为什么这里用 BFS 而不是 DFS？
2. visited 应该在入队时标记还是出队时标记？
3. 拓扑排序如何判断有环？
4. 并查集复杂度为什么近似 O(1)？
5. 如果边有权重怎么办？

标准回答方向：
- 最短路无权 -> BFS
- 入队时标记避免重复入队
- 拓扑处理节点数 < n 表示有环
- 路径压缩 + 按秩合并
- 有权最短路切换 Dijkstra

## 60 秒口播模板

树题口播：
- 这是树递归题，我定义 `dfs(node)` 返回 `...`。
- 递归终止是 `...`。
- 当前节点由 `left/right` 合并得到 `...`。
- 全局答案在 `...` 处更新。
- 时间 O(n)，空间 O(h)。

图题口播：
- 我先建模：节点是 `...`，边是 `...`。
- 因为题目求 `最少步数/连通性/依赖顺序`，我选 `BFS/DFS/拓扑`。
- `visited` 在 `入队时` 标记，避免重复状态。
- 每个节点边最多处理一次，复杂度 O(V+E)。
